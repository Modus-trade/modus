# Соответствие ТЗ и обращению директора

Сверка решения с «ТЗ на разработку системы обратной связи и предложений сотрудников» и видеообращением директора ГК «Модус Трейд».
Подробности к [главному README](../README.md).

## Что просил директор

| Запрос из видео | Как решено |
| --- | --- |
| Вопросы приходят хаотично: почта, совещания, устные разговоры | Единая точка подачи на сайте и в iOS-приложении, обращение подаётся за минуту с фото и файлами |
| Сотрудник думает, что вопрос решается, а о нём забыли | Срок первого ответа (SLA) для каждой категории; центр внимания показывает просроченные, без ответственного и без движения |
| Команда перестанет предлагать, если ничего не решается | Автор видит стадию и обязательный мотивированный результат: «Реализовано» или «Отклонено» с причиной |
| Директор хочет видеть, какие вопросы требуют решения и какие есть предложения | Аналитика по типам, категориям и статусам, повторяющиеся проблемы, центр внимания администратора |
| Сотрудник понимает стадию: разработка, принятие решения, реализация | Линия стадий в карточке на сайте и в приложении: Подано → Рассмотрение → Реализация → Решение |
| Сотрудник может задавать уточняющие вопросы о статусе | Обсуждение в карточке; руководитель может запросить уточнение, ответ автора возвращает обращение на рассмотрение |

## Основной сценарий ТЗ (2.3)

| Шаг | Реализация |
| --- | --- |
| Выбор категории | 18 категорий; форма сразу показывает, назначится ли ответственный автоматически, и срок первого ответа (в приложении — и имя ответственного) |
| Описание, предполагаемое решение, материалы | Поля «Описание» и «Предполагаемое решение», вложения до 10 МиБ: фото с камеры, PDF, DOCX, XLSX |
| Регистрация и направление ответственному | Номер A-XXX, ответственный по правилу категории; если ответственного нет — «Нераспределённые» |
| Рассмотрение, решение и действия | Статусы по серверной матрице переходов; без результата завершить нельзя |
| Автор отслеживает статус и результат | Стадии, история, уведомления в реальном времени |
| Сохранение для анализа повторяющихся проблем | Полная история в базе, аналитика, похожие и повторяющиеся проблемы |

## Процесс рассмотрения (2.5)

- **Как попадает к ответственному:** у каждой категории есть ответственный. Если он отключён или его нет, обращение попадает в «Нераспределённые», и администратор видит его в центре внимания.
- **Как фиксируются статус и результат:** переходы проверяет сервер, каждое изменение пишется в историю с автором и временем, а результат обязателен для завершения.
- **Как автор узнаёт о ходе работы:** стадии в карточке, история и мгновенное уведомление о назначении, комментарии, вопросе, смене статуса и результате.
- **Как предотвращается потеря обращений:** SLA первого ответа, нераспределённые обращения и обращения без движения 3–30 дней видны в центре внимания.
- **Как выявляются повторяющиеся проблемы:** поиск похожих при подаче, присоединение к общей проблеме и блок «Повторяющиеся проблемы» у руководителя.
