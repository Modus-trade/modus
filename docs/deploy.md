# Сервер и автодеплой

Подробности к [главному README](../README.md).

## Что работает на сервере

| Компонент | Где | Как |
| --- | --- | --- |
| Сайт | `/srv/modus/frontend/dist` | статика отдаётся через nginx |
| API | `127.0.0.1:8021` | uvicorn под systemd (`modus-backend`), пользователь `modus` без root |
| База | PostgreSQL 16 в Docker | слушает только `127.0.0.1`, извне недоступна |
| HTTPS | nginx + Let's Encrypt | сертификаты продлеваются автоматически |

nginx проксирует `/api/*` в FastAPI и `/api/ws` как WebSocket, а все остальные пути отдаёт как одностраничное приложение.
Секреты (`DATABASE_URL`, `JWT_SECRET`) лежат в `/srv/modus/backend.env` на сервере и в git не попадают.

## Автодеплой

Оба рабочих репозитория содержат `.github/workflows/deploy.yml`, который запускается при пуше в `main`.

**modus-back**
1. `pytest` на временной SQLite.
2. `rsync` кода в `/srv/modus/backend`.
3. `scripts/deploy.sh`: venv и зависимости → `alembic upgrade head` → перезапуск сервиса → ожидание ответа `/api/health`.
4. Копия кода в `modus/backend`.

**modus-front**
1. `npm ci`, `npm test`, `npm run build`.
2. `rsync` сборки: сначала ассеты, `index.html` последним, поэтому сайт обновляется без простоя.
3. Копия кода в `modus/frontend`.

Если любой шаг падает, следующие не запускаются и на сервере остаётся прошлая версия.
Деплой идёт по SSH-ключу пользователя `modus`. Этому пользователю через sudo разрешено только перезапускать свой сервис и смотреть его логи.

## Как изменить базу

Создайте миграцию в `modus-back`:

```sh
alembic revision --autogenerate -m "что изменилось"
```

Проверьте сгенерированный файл, закоммитьте и запушьте. На сервере она применится сама при деплое.
